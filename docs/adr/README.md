# Registro de decisiones de arquitectura (ADR)

Cada ADR explica una decisión de diseño de PrestaLab: el problema, la opción elegida, las alternativas
descartadas y lo que se gana y se pierde con ella. Se escriben en el formato de Michael Nygard.

| ADR | Decisión | Estado |
|---|---|---|
| [0001](0001-api-rest-stateless-con-jwt.md) | API REST stateless autenticada con JWT HS256 | Aceptada |
| [0002](0002-arquitectura-en-capas-verificada.md) | Arquitectura en capas verificada con ArchUnit | Aceptada |
| [0003](0003-errores-con-problemdetail.md) | Errores con ProblemDetail (RFC 9457) y códigos propios | Aceptada |
| [0004](0004-estados-del-prestamo-en-el-dominio.md) | Las transiciones del préstamo viven en la entidad | Aceptada |
| [0005](0005-login-uniforme-y-cuentas-desactivadas.md) | Login uniforme y cuentas desactivadas con token vigente | Aceptada |
| [0006](0006-estrategia-de-pruebas.md) | Estrategia de pruebas en cuatro niveles | Aceptada |
